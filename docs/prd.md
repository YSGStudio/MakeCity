# PRD: 우리 마을 가꾸기 3D — 바다 마을 · 산 마을 · 들 마을

- 문서 상태: 현재 구현(v2, 들 마을 추가판)을 기준으로 정리한 계획서
- 산출물: 단일 HTML 파일 `village3d.html` (claude.ai 아티팩트로 배포)
- 대상 교과: 초등 사회 — 지형(바다·산·들)에 따른 생활 모습과 지역(도시) 변화

---

## Summary

학생이 **바다 마을, 산 마을, 들 마을** 세 가지 지형 위에서 1970년부터 2030년까지
5년 단위로 시간을 흘려보내며 건물을 짓고 마을을 가꾸는 **로우폴리 3D 도시 건설 게임(심시티형)**이다.
지형마다 지을 수 있는 시설과 조건이 달라서, 학생은 직접 지어 보면서
"왜 바닷가에는 항구가, 산지에는 계단식 밭이, 들판에는 도시 시설이 많이 생기는가"를 경험으로 알게 된다.
수업 시연용 **자동 발전 보기**와, 세 마을을 나란히 보는 **마을 비교** 화면을 함께 제공한다.

## Problem And Goal

**문제**
- 지형에 따라 지역의 생활 모습과 도시의 변화 과정이 달라진다는 내용은 교과서 사진과 글만으로는
  학생이 "왜 그런지" 체감하기 어렵다.
- 시간에 따른 지역 변화(산업화, 도시화, 인구 이동, 환경 문제)를 한 화면에서 비교해 볼 도구가 부족하다.

**목표**
1. 학생이 지형(높이, 경사, 바다·강과의 거리)이 시설 입지를 결정한다는 것을 규칙으로 직접 경험한다.
2. 1970~2030년의 시대 흐름에 따라 마을이 바뀌는 모습을 3D로 관찰한다.
3. 세 마을의 인구·시설·환경을 비교하고 토의 질문으로 정리한다.
4. 설치 없이 브라우저 링크 하나로 교실 PC와 태블릿에서 실행한다.
5. 한 차시(40분) 안에 끝내는 활동이므로 서버나 데이터베이스는 두지 않는다. 대신 실수로 새로고침하거나 탭을 닫아도 진행이 사라지지 않도록 **브라우저에 자동 저장**한다.

## Users And Use Cases

| 사용자 | 사용 장면 |
|---|---|
| 교사 | 수업 도입에서 **▶ 자동 발전 보기**로 60년 변화를 시연하고, **⚖️ 마을 비교**로 토의를 이끈다. |
| 학생(초등 3~6학년) | 마을 하나를 골라 직접 건물을 짓고, 미션을 해결하며, 실패 메시지(예: "바다와 맞닿은 땅에만 지을 수 있어요")로 입지 조건을 배운다. |
| 모둠 | 모둠마다 다른 마을을 맡아 키운 뒤 비교 화면으로 결과를 발표한다. |

주요 흐름
1. 상단 탭에서 마을(🌊/⛰️/🌾)을 고른다.
2. 땅에 마우스를 올려 지형 종류, 해발 높이, 경사를 확인한다.
3. 왼쪽 도구를 골라 땅을 클릭해 짓는다. 도로·농경지·숲·철거는 드래그로 여러 칸을 칠할 수 있다.
4. **⏩ 5년 지나기**로 시간을 흘리면 인구·예산·환경이 바뀌고 시대 이야기가 나온다.
5. 2030년에 결과 창을 보고, **⚖️ 마을 비교**에서 세 마을을 비교하며 토의 질문에 답한다.
6. 도중에 새로고침하거나 브라우저를 다시 열어도, 같은 기기·같은 브라우저라면 세 마을이 마지막 상태로 돌아온다.

## Non-Goals

- 데이터베이스, 서버, 로그인, 학생별 계정. 저장은 브라우저 localStorage에만 한다.
- 다른 기기나 다른 브라우저로 진행을 옮기기, 파일로 내보내기/불러오기, 여러 저장 슬롯.
- 차시를 넘겨 장기간 기록을 보관하는 것 (한 차시 안에서 끝내는 활동이 전제).
- 여러 학생이 같은 마을을 동시에 편집하는 실시간 협업.
- 실제 지도·실제 지역 데이터 사용 (지형은 규칙으로 생성한 가상 지형이다).
- 정밀한 경제·교통 시뮬레이션 (교통 체증, 전력망, 수도 같은 심시티 세부 시스템).
- 건물 회전·업그레이드, 여러 칸을 차지하는 대형 건물.
- 효과음과 배경음악.
- 4번째 지형(섬, 강 하구 등) 추가.

## Requirements

### 지형과 지도
- **R1** 20×20 칸의 격자 지도 3종을 제공한다. 지형은 무작위가 아니라 고정된 규칙(결정적 노이즈)으로 만들어 매번 같은 모양이 나온다.
  - 바다 마을: 바다 → 모래사장 → 넓은 평지 → 뒤쪽 낮은 언덕/바위
  - 산 마을: 가운데 굽이치는 강, 강 옆의 좁은 평지, 바깥으로 갈수록 가팔라지는 비탈, 바위산, 눈 덮인 봉우리
  - 들 마을: 넓은 평지, 남쪽을 굽이쳐 흐르는 강, 한쪽 구석의 낮은 언덕
- **R2** 칸마다 높이(0.25 단위 계단)와 지형 종류(바다/강/모래/풀밭/바위/눈)를 가진다. 경사는 물이 아닌 이웃 4칸과의 높이 차 가운데 가장 큰 값으로 정한다.
- **R3** 로우폴리 3D(평면 음영, 계단형 지형 블록, 출렁이는 물 표면, 떠다니는 구름)로 그린다.

### 건설 도구와 입지 규칙
- **R4** 다음 도구를 제공하고, 해금 연도 전에는 잠금 표시와 함께 지을 수 없다.

- **R5** 지을 수 없는 칸을 누르면 이유를 문장으로 보여 준다(예: "강이 좁고 얕아 큰 배가 다닐 수 없어요", "도로 옆에만 지을 수 있어요"). 예산이 모자라면 예산 부족 안내를 보여 준다.
- **R6** 마우스를 올린 칸에 지형 이름, 해발 높이(높이×80m), 경사 정도, 있는 건물, 현재 도구로 지을 수 있는지와 비용을 말풍선으로 보여 주고, 칸 표시를 초록(가능)/빨강(불가)으로 칠한다.
- **R7** 지형 이해와 관련된 건물을 처음 지으면 한 번만 지리 설명 힌트를 띄우고 기록에 남긴다(논, 계단식 밭, 항구, 비탈 도로, 공장 입지, 해수욕장, 스키장, 방풍림, 산림, 도시 시설 7종, 놀이공원, 다리, 풍력).

### 시간 흐름과 시뮬레이션
- **R8** 각 마을은 1970년에 작은 마을(도로·주택·농경지 몇 칸)과 예산 2,000으로 시작한다. **⏩ 5년 지나기**를 누르면 5년이 흐르고 2030년에 끝난다.
- **R9** 5년마다 다음을 계산한다.
  - 집(수용 인원) = 주택×5 + 아파트×30
  - 일자리 = 논×3, 계단식 밭×2, 항구×12, 공장×25, 상가×10, 관광지×15, 풍력×3, 학교×8, 기차역×10, 병원×15, 공원×1, 대형마트×20, 고층빌딩×40, 경기장×10
  - 환경(0~100) = 100 − 공장×8 − 항구×2 − 아파트×1 − 도로×0.2 − 고층빌딩×1.5 − 대형마트×1 − 경기장×1 + 숲×1.2 + 풍력×1 + 공원×5
  - 목표 인구 = min(집, 일자리×2 + 10). 인구는 목표 쪽으로 늘거나 줄어든다. 환경이 40 미만이면 느리게 는다.
  - 산 마을은 1980~1995년에 관광지가 없으면 목표 인구가 25% 줄어든다(인구 유출).
  - 인구 80명 이상인데 학교가 없거나, 200명 이상인데 병원이 없으면 목표 인구가 각각 15% 줄어든다.
  - 기차역이 있으면 목표 인구가 10% 늘어난다(집 수 한도 안에서).
  - 예산 += 세금(인구×4) + 시설 수입 − 유지비. 관광지와 경기장 수입은 환경 점수에 비례한다.
- **R10** 5년이 지날 때마다 기록에 시대 이야기, 인구 변화, 5년 수입, 새로 해금된 시설, 부족한 것(일자리/집/학교/병원/환경)을 남긴다.
- **R11** 마을마다 1970~2030년의 시대 이야기 13개를 보여 준다. 바다 마을은 어촌 → 산업화 → 관광 → 해양 환경, 산 마을은 산촌 → 도로 연결 → 인구 유출 → 스키장·생태관광 → 귀농, 들 마을은 농촌 → 철도 → 공업 단지 → 도시화 → 도심 → 녹지 부족 → 농지 감소 순서로 이어진다.

### 미션과 결과
- **R12** 마을마다 미션 5개를 보여 주고, 달성하면 체크하고 알림을 띄운다.
  - 바다: 항구 2개 / 공장 1개 / 해수욕장 / 인구 400 / 2010년 이후 환경 60 이상
  - 산: 계단식 밭 3개 / 도로 20칸 / 스키장 / 숲 15칸 / 인구 250
  - 들: 학교와 병원 / 기차역 / 고층빌딩 3개 / 인구 800 / 공원 3개와 2010년 이후 환경 50 이상
- **R13** 2030년이 되면 결과 창(시작 인구 → 최종 인구, 일자리, 환경, 미션 달성 수)을 보여 준다.

### 비교와 시연
- **R14** **⚖️ 마을 비교** 창에 세 마을의 인구 변화 꺾은선 그래프(마을별 색), 연도·인구·일자리·환경·예산과 시설 18종의 개수 표, 토의 질문 6개를 보여 준다.
- **R15** **▶ 자동 발전 보기**는 2.2초마다 미리 정한 연도별 건설 계획(PLAN)에 따라 무료로 건물을 짓고 5년을 넘긴다. 2030년이 되거나 ⏸를 누르면 멈춘다. 다른 마을로 바꾸거나 5년 지나기/비교를 누르면 자동 진행을 멈춘다.
- **R16** 세 마을은 상태를 따로 가진다. 탭을 바꿔도 각 마을의 진행 상황이 유지된다. **↺ 다시 시작**은 지금 보고 있는 마을만 1970년으로 되돌린다.

### 브라우저 저장
- **R21** 데이터베이스는 쓰지 않는다. 각 마을의 상태를 브라우저 `localStorage`에 마을별 키(`village3d:v1:coast`, `village3d:v1:mountain`, `village3d:v1:plain`)로 저장한다.
- **R22** 저장하는 값은 간단한 데이터만이다: 연도, 인구, 예산, 인구 기록(`hist`), 마을 기록 최근 60개, 이미 본 힌트, 달성한 미션, 자동 도로 계획 진행 위치(`roadIdx`), 건물 목록 `[{x, z, b, variant}]`. 지형은 고정 규칙으로 다시 만들 수 있으므로 저장하지 않는다. 한 마을 저장 크기는 50KB 이하로 유지한다.
- **R23** 건물을 짓거나 철거할 때, 5년이 지날 때, 자동 발전이 한 단계 진행될 때마다 자동 저장한다. 연속 칠하기 중에는 손을 뗀 뒤 한 번만 저장해도 된다.
- **R24** 페이지를 열면 저장된 마을이 있는지 확인한다. 있으면 지형을 만든 뒤 건물 목록을 다시 지어(애니메이션·힌트 없이) 마지막 상태로 되돌리고, "💾 지난번 마을을 불러왔어요" 알림을 띄운다. 없으면 1970년 시작 마을을 만든다.
- **R25** **↺ 다시 시작**은 지금 보는 마을의 저장 데이터를 지우고 1970년으로 되돌린다. 실수를 막기 위해 페이지 안의 확인 창("정말 처음부터 다시 할까요?")을 거친다(브라우저 `confirm`은 쓰지 않는다).
- **R26** 저장소를 쓸 수 없는 환경(사생활 보호 모드, 저장 공간 부족, 접근 거부)에서는 모든 읽기·쓰기를 `try/catch`로 감싸 게임은 그대로 진행되게 하고, 위쪽 현황에 "⚠️ 저장 안 됨"을 작게 표시한다. 저장된 값이 깨져 있거나 버전이 다르면 무시하고 새 마을로 시작한다.
- **R27** 위쪽 현황 옆에 마지막 저장 상태를 작게 보여 준다(예: "💾 저장됨").

### 화면과 조작
- **R17** 화면 배치: 위쪽에 제목·마을 탭·현황(연도, 인구, 예산, 집, 일자리, 환경 이모지), 왼쪽에 2열 도구 상자('🏙️ 도시 시설' 구분선 포함), 오른쪽에 정보 패널(지형 이야기, 시대 이야기, 미션, 인구 그래프, 마을 기록), 아래쪽에 진행 버튼.
- **R18** 카메라: 둘러보기 도구에서는 왼쪽 드래그로 회전, 휠로 확대·축소, 오른쪽 드래그로도 회전한다. 칠하기 도구(도로·농경지·숲·철거)에서는 왼쪽 드래그로 여러 칸을 칠한다.
- **R19** 화면 폭이 900px 이하이면 정보 패널을 숨기고 **📋 정보** 버튼으로 연다. 터치 탭으로도 지을 수 있다.
- **R20** 건물이 생길 때 커지며 나타나는 애니메이션이 있고, 풍차·관람차는 돌며, 공장 연기는 피어오르고, 배는 출렁이고, 기차는 움직인다.

## Acceptance Criteria

- **AC1** 페이지를 열면 3초 안에 바다 마을 3D 지도가 보이고, 브라우저 콘솔에 오류가 없다. (브라우저/Playwright)
- **AC2** 세 탭을 누르면 각각 바다(바다+모래사장), 산(강+계곡+봉우리), 들(넓은 평지+강+구석 언덕) 지형이 보이고, 지형 이야기 문구가 바뀐다. (브라우저)
- **AC3** 산 마을이나 들 마을에서 항구를 누르면 짓지 못하고 이유 문구가 뜬다. 바다 마을에서 바다와 맞닿은 칸에는 항구가 지어진다. (브라우저)
- **AC4** 같은 농경지 도구로 평지에는 논, 비탈에는 계단식 밭이 지어지고, 각각 처음 지을 때 힌트가 한 번 뜬다. (브라우저)
- **AC5** 1990년 전에는 아파트 버튼이 🔓 대신 "🔒 1990년"으로 표시되고 지을 수 없다. 1990년이 되면 기록에 "🔓 새로 지을 수 있어요"가 남는다. (브라우저)
- **AC6** 도로 옆이 아닌 칸에 학교·병원·고층빌딩을 지으려 하면 "도로 옆에만 지을 수 있어요"가 뜬다. (브라우저)
- **AC7** 강 위에 도로를 지으면 다리 모형이 생기고 비용이 40 줄어든다. (브라우저)

- **AC9** 세 마을 모두 자동 발전 보기를 끝까지 돌리면 오류 없이 2030년에 도달한다. 참고 결과(현재 구현): 인구는 바다 약 370명, 산 약 120명, 들 약 1,000명이고, 들 마을 환경은 50 이상이다. 결과는 들 > 바다 > 산 순서여야 한다. (Playwright 자동 실행)
- **AC10** 비교 창의 표에 세 마을 열과 시설 18종 행이 있고, 그래프에 색이 다른 선 3개가 그려진다. (브라우저)
- **AC11** 바다 마을을 2000년까지 진행한 뒤 산 마을로 갔다 돌아오면 바다 마을이 2000년 상태 그대로다. 다시 시작은 보던 마을만 1970년으로 되돌린다. (브라우저)
- **AC12** 폭 800px 화면에서 정보 패널이 숨겨지고 📋 정보 버튼으로 열리고 닫힌다. (브라우저 반응형 보기)
- **AC13** 들 마을에서 인구가 80명을 넘었는데 학교가 없으면 5년 지나기 뒤 기록에 학교가 없다는 안내가 남는다. (브라우저)
- **AC14** 바다 마을에 건물을 몇 개 짓고 1990년까지 진행한 뒤 새로고침하면 같은 연도·인구·예산·건물·미션 체크·기록으로 돌아오고 "지난번 마을을 불러왔어요" 알림이 뜬다. (브라우저 / Playwright에서 `page.reload()`)
- **AC15** 개발자 도구의 Local Storage에 `village3d:v1:coast` 같은 마을별 키가 보이고, 값은 JSON이며 크기가 50KB 이하다. 데이터베이스나 외부 서버로 가는 네트워크 요청은 없다. (브라우저 개발자 도구 / Playwright `localStorage` 읽기)
- **AC16** 다시 시작에서 확인 창이 뜨고, 확인하면 그 마을의 키만 지워져 1970년으로 돌아간다. 다른 두 마을의 저장은 그대로다. (브라우저)
- **AC17** `localStorage`가 막힌 환경(Playwright에서 `setItem`이 예외를 던지도록 바꿈)에서도 콘솔 오류 없이 게임이 진행되고 "⚠️ 저장 안 됨"이 보인다. 키에 깨진 값을 넣고 새로고침해도 새 마을로 정상 시작한다. (Playwright)

## Technical Structure And Changes

- **스택**: 기본값인 React + Next.js 대신 **단일 HTML 파일 + three.js(ES 모듈, import map)**를 쓴다. 이유: 설치·빌드 없이 링크 하나로 교실에서 바로 열 수 있어야 하고, claude.ai 아티팩트로 배포하기 때문이다.
- **데이터베이스 없음 (사용자 결정).** 한 차시 안에서 끝내는 활동이라 서버와 DB를 두지 않는다. 데이터베이스 확정 규칙은 "DB 미사용"으로 확정했다.
- **브라우저 저장(localStorage)**
  - 키: `village3d:v1:<type>` (type = `coast` | `mountain` | `plain`). 키 이름의 `v1`은 저장 형식 버전이다. 형식이 바뀌면 `v2`로 올려 옛 데이터를 무시한다.
  - 값(JSON): `{ v:1, type, year, pop, money, hist:[{year,pop}], logs:[{year,text}](최근 60개), hints:{}, done:{}, roadIdx, buildings:[{x,z,b,variant}] }`
  - 새 모듈: `store.save(M)`, `store.load(type)`, `store.clear(type)`. 모두 `try/catch`로 감싸고 실패하면 `false`/`null`을 돌려준다.
  - 저장 시점: `place()`(칠하기 중이면 pointerup 때), `nextTurn()` 끝, 자동 발전 각 단계.
  - 불러오기: `makeMap(type)`에서 지형과 도로 계획을 만든 뒤 `store.load(type)`이 있으면 `START_PRESET` 대신 건물 목록을 `place(..., free=true)`로 다시 짓고 나머지 값을 덮어쓴다. 다시 지을 때 `M.ready=false`로 두어 애니메이션과 힌트를 막는다.
  - `↺ 다시 시작`: 페이지 안 확인 모달 → `store.clear(type)` → `makeMap(type)`.
  - 아티팩트 환경에서 localStorage는 보는 사람의 브라우저에만 남고 다른 기기와 공유되지 않으며, 비어 있거나 예외가 날 수 있다는 전제로 만든다.
- **환경 변수 없음. 외부 네트워크 저장 없음.**
- **코드 구조** (`village3d.html` 하나에 모두 들어 있음)
  - 설정·데이터: `TOOLS`, `HINTS`, `TERRAIN_DESC`, `ERA`, `MISSIONS`, `START_PRESET`, `PLAN`, `COLORS`, `MNAME`
  - 지형: `genTerrain`, `buildTerrain`, `makeRoadPlan`, `slope`, `nbrs`, `adjRoad`, `adjSea`
  - 규칙: `check(M, tool, tile)` → `{ok, cost, msg, hint, variant}`
  - 모델: `buildMesh(M, tool, tile)` (Box/Cone/Cylinder로 만든 로우폴리 그룹과 `userData.anim`)
  - 시뮬레이션: `calc`, `simulate`, `nextTurn`, `place`, `autoPlace`, `startAuto`/`stopAuto`
  - 화면: `renderTools`, `updateUI`, `drawChart`(Canvas 2D), `compareHTML`, `showEnd`, `showTip`, `toast`
  - 입력: 레이캐스트로 칸 고르기(`pick`), pointer 이벤트로 클릭/드래그 칠하기, OrbitControls로 카메라 조작
- **마을 상태 객체 `M`**: `type`, `year`, `pop`, `money`, `env`, `jobs`, `housing`, `tiles[]`, `tileMeshes[]`, `group`, `hist[]`, `logs[]`, `hints{}`, `done{}`, `roadPlan`, `cx/cz`(마을 중심)
- **배포**: claude.ai 아티팩트(`publish_files`, `index.html`). 아티팩트 보안 정책상 jsDelivr와 Google Fonts는 불러올 수 있다.
- **환경 변수 없음.**

## Risks And Open Decisions

- **저사양 기기 성능**: 마을마다 칸 메시 400개와 건물 수백 개에 그림자를 그린다. 오래된 크롬북에서 느리면 그림자 끄기나 InstancedMesh가 필요할 수 있다. (미확정)
- **CDN 의존**: 학교 방화벽이 jsDelivr나 Google Fonts를 막으면 게임이 뜨지 않거나 글꼴이 바뀐다. 막히면 three.js를 파일 안에 넣는 방법을 검토한다.
- **브라우저 저장의 한계**: 저장은 그 기기·그 브라우저에만 남는다. 학생이 다른 PC로 옮기면 이어서 할 수 없다(차시 안에서 끝내므로 허용).
- **공용 PC**: 앞 반 학생의 마을이 다음 반에 그대로 보일 수 있다. 수업 시작 때 **↺ 다시 시작**을 누르도록 안내한다. "세 마을 모두 지우기" 버튼은 이번 범위에 넣지 않는다. (필요하면 결정)
- **저장 실패 환경**: 사생활 보호 모드나 학교 보안 설정으로 저장이 막힐 수 있다. 이때도 게임은 되지만 새로고침하면 처음으로 돌아간다. 화면 표시로만 알린다.
- **균형 수치**: 인구·예산 공식은 자동 발전 결과(들 > 바다 > 산)를 기준으로 맞췄다. 학생이 직접 할 때 예산이 너무 많거나 적은지는 사람 검증으로 조정한다.
- **교과 정확성**: 시대 이야기는 우리나라 지역 변화를 단순화한 것이다. 연도와 사건은 실제 지역마다 다를 수 있으므로 교사 검토가 필요하다.
- **아티팩트 공유**: 지금은 소유자만 볼 수 있다. 학생에게 나누려면 소유자가 아티팩트 페이지에서 공유를 켜야 한다.
